# EG-RSA Single-Chain Bootstrap and Iteration

This folder implements a single-chain EG-RSA reward-search path. It does not use Eureka-style multi-candidate sampling. Each iteration trains exactly one reward function, reflects on the measured result, and generates one revised reward.

## Bootstrap pipeline

```text
task_description.txt + step.py
  -> EnvironmentUnderstandingAgent
  -> environment_understanding.json
  -> TargetAlignmentAgent
  -> target_alignment_contract.json
  -> InitialRewardSchemaAndCodeAgent
  -> initial_reward_schema_and_code.json
  -> reward_schema.json + reward_code.py
  -> append compute_reward into copied Eureka env_code/env.py
  -> PPO training
  -> evals.json + component_metrics.json + trajectory_summary.json + reward_trace.json
```

Run bootstrap only:

```bash
python -m eg_rsa.run_single_chain --config eg_rsa/single_chain/configs/lunar_lander.yaml
```

## Iterative pipeline

```text
iter_000 training artifacts
  -> EvidenceBuilder
  -> iteration_evidence.json
  -> MemoryManager retrieves compact memories
  -> ReflectionAgent
  -> reflection_decision.json
  -> RewardRevisionAgent
  -> revised_reward_schema_and_code.json
  -> validation + copied env_code/env.py
  -> PPO training for iter_001
  -> MemoryManager records before -> edit -> after transition
```

Run bootstrap plus one revision/training iteration:

```bash
python -m eg_rsa.run_single_chain_iterative --config eg_rsa/single_chain/configs/lunar_lander.yaml
```

Continue from an existing bootstrap run directory without rerunning iter_000:

```bash
python -m eg_rsa.run_single_chain_iterative \
  --config eg_rsa/single_chain/configs/lunar_lander.yaml \
  --bootstrap-run-dir experiments/eg_rsa_single_chain/lunar_lander_single_chain_YYYYMMDD_HHMMSS
```

The iterative runner creates:

```text
<run_dir>/
  iteration_evidence.json
  best_iteration_evidence.json
  environment_understanding_summary.json
  target_alignment_summary.json
  memory/reward_memory.jsonl
  search/
    reflection_decision.json
    reflection_raw.txt
    revised_reward_schema_and_code.json
    reward_revision_raw.txt
  iterations/iter_001/
    reward/reward_schema.json
    reward/reward_code.py
    reward/validation_report.json
    env_code/env.py
    training/final_eval.json
    training/evals.json
    training/component_metrics.json
    training/trajectory_summary.json
    training/reward_trace.json
    iteration_evidence.json
    memory_transition.json
```

## Design choices

- The three bootstrap JSON files are generated by the LLM every run. Their contents are not hard-coded.
- EnvironmentUnderstandingAgent now outputs `behavior_trajectory_prior` so reward generation can reason about likely successful trajectories and bad local optima.
- TargetAlignmentAgent now outputs phase-aware objectives, bad local optima, and edit-scope policy.
- InitialRewardSchemaAndCodeAgent now separates `component_catalog`, `active_reward_terms`, `diagnostic_terms`, and `dormant_terms`.
- Future reward revisions are not artificially limited to a fixed number of changed terms. The LLM may propose small, large, or restructuring edits, but must declare edit scope, reason, risks, expected metric changes, and validation metrics.
- EvidenceBuilder and MemoryManager are deterministic. They compress metrics and record measured before/after transitions; they do not invent training outcomes.
