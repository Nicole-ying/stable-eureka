# Operating Mode — DETERMINE THIS FIRST

Check the diagnostics. Your edit strategy depends on which mode you're in:

**COLD START mode** — if success_like_terminal_rate is 0% AND the dominant failure is early
(out-of-bounds, crash, or very short episodes < 150 steps):

  The reward is fundamentally missing something. The agent cannot even APPROACH success.
  Your job: identify the MISSING signal and ADD it.

  In cold start mode:
  - ADDING a new progress signal IS allowed and EXPECTED when none exists for a required behavior
  - Look for: missing spatial centering, missing descent guidance, missing stability feedback
  - The "don't add new components" rule does NOT apply — the reward is structurally incomplete
  - Focus on the most basic missing behavior first (can the agent even stay on the screen?)

**FINE-TUNE mode** — if success_like_terminal_rate > 0% OR the agent reaches the task vicinity
(episode_length > 300, near the target state):

  The reward structure is viable but needs balancing. Your job: fix component interactions.

  In fine-tune mode:
  - Prefer editing existing components over adding new ones
  - Fix scale imbalances, farming vulnerabilities, and semantic errors
  - Only add a new component if a specific phase is unreachable with current signals

# Diagnostic Order

Answer these questions in your Diagnosis section:

1. **What does the agent actually do?** Look at behavior_summary, trajectory examples, and
   terminal outcome distribution. What percentage reaches each outcome?

2. **Which component dominates the return?** Check component_means. If one component has
   abs_return > 3× the next largest, it IS dominating training regardless of your intent.

3. **Why is the agent choosing this behavior?** Trace the reward: which components REWARD
   the observed behavior? Which components PENALIZE the behavior you want?

4. **What is missing or broken?**
   - Missing: a required behavior has zero reward signal
   - Broken: a component fires under wrong conditions, has wrong scale, or can be farmed
   - Semantic error: terminal condition doesn't match the environment document

## Common Failure Patterns

- **Spatial drift / OOB**: Agent flies off-screen. Root cause: NO signal rewards staying near
  the target zone. Fix: ADD a centering progress signal (approach x=0, or penalty for |x| > margin).
- **Reward farming**: A positive component fires every step, dominates return, but success=0.
  Fix: convert to delta form or one-shot gating.
- **Timeout hovering**: Agent reaches target vicinity but never completes the task. Dense progress
  signals pay more than the one-shot terminal bonus. Fix: reduce farmable progress OR increase
  terminal objective scale OR add timeout penalty near the ground.
- **Action collapse**: Agent uses only 1-2 actions at >90% probability. Fix: add positive signal
  that REQUIRES the unused action, or check if penalties make all actions costly.
- **Penalty dominance**: Most components are negative → agent learns passivity.
  Fix: convert penalties to delta-form progress signals where possible.
- **Single component dominance**: One auxiliary term > 3× terminal objective. The agent optimizes
  the auxiliary, not the task. Fix: reduce that component's scale or convert to one-shot.

## Editing Rules (mode-dependent)

In BOTH modes:
- Edit only what needs to change. If the terminal condition is correct, don't touch it.
- Record your hypothesis: what you changed, why, what you expect, what evidence will confirm/refute.
- One conceptual change per iteration. If you must co-edit two components, explain why they're coupled.

In COLD START mode:
- ADD the missing structural signal. Do not tune scales of existing components that are not the problem.
- If the agent can't stay on screen, fixing the fuel penalty won't help. Add centering.

In FINE-TUNE mode:
- Fix the dominant problem component. Don't add new ones to work around it.
- Do NOT tune multiple scales at once.
- If the agent already succeeds sometimes, make SMALL adjustments only.

## Anti-Patterns (NEVER do these)

- NEVER remove a critical signal (crash penalty, terminal bonus) without replacing its function
- NEVER add a penalty to suppress behavior that a positive signal could redirect
- NEVER change more than 3 components in one edit
- NEVER repeat edit patterns listed as ❌ Avoid in the Memory Context
